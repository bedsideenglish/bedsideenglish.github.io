# 진료과별 Model History Taking 웹페이지 기획안

- 문서 상태: 1차 10개 공개 완료, 나머지 15개 기획
- 작성일: 2026-08-27
- 대상: Bedside English Android 앱 사용자
- 구현 범위: 10개 정적 HTML·사전 생성 WAV 공개 완료. 이 문서는 후속 시나리오의 구조 기준도 겸한다.
- 기준 콘텐츠: Android Encounter 탭의 25개 진료과와 현재 case JSON

## 0. 제작 상태

- **공개 및 TTS 완료 (10개):** 1) 소화기, 2) 심장혈관, 3) 신경과, 4) 호흡기, 5) 내분비, 12) 정형외과, 17) 산부인과, 18) 소아청소년과, 19) 정신건강의학과, 23) 응급의학과
- **미작성 (15개):** 위 두 목록에 포함되지 않은 시나리오
- 공개 10개 대본의 source of truth는 `model-interview-pages.json`이다. `model-interview-drafts.json`은 2026-08-28에 승격한 추가 5개의 검토 이력을 보존한다.

## 1. 결론

이 콘텐츠는 만드는 편이 좋다.

기존 `learning/` 페이지가 질문 표현, 표현 선택 이유, 대체 문장 등을 설명하는 **해설형 자료**라면, 새 콘텐츠는 처음부터 끝까지 이어지는 **완성형 모델 문진**이어야 한다. 사용자는 페이지를 연 직후 별도의 이론 설명 없이 다음 세 가지를 바로 볼 수 있어야 한다.

1. 어떤 상황인지
2. 의사가 실제로 어떤 순서로 묻는지
3. 환자의 답을 받아 다음 질문으로 어떻게 넘어가는지

따라서 기존 `learning/`의 하위 유형으로 억지로 넣기보다, 별도 라이브러리인 `model-interviews/` 또는 `history-taking/`으로 분리하는 것을 권한다.

## 2. 이 콘텐츠의 한 문장 정의

> 한 명의 환자를 상대로, 해당 진료과에서 놓치면 안 되는 질문을 자연스러운 영어 대화 한 편 안에 담은 모델 문진.

## 3. 콘텐츠 원칙

### 반드시 지킬 것

- **대화가 주인공이다.** 첫 화면에서 긴 소개문이나 학습 목표를 보여주지 않는다.
- **증상 중심 제목을 쓴다.** 정답 진단명을 제목에서 먼저 공개하지 않는다.
- **한 페이지에는 한 환자, 한 방문 목적만 둔다.** 여러 질환을 한꺼번에 가르치지 않는다.
- **질문 목록이 아니라 대화 흐름을 보여준다.** 환자의 답이 다음 질문을 유발해야 한다.
- **미국식 임상 영어(`en-US`)를 사용한다.** 현재 공개 learning 콘텐츠의 기준과 맞춘다.
- **환자에게 자연스러운 표현을 사용한다.** 전문용어가 필요하면 의사가 쉬운 말로 바로 풀어 말한다.
- **민감한 질문에는 전환 문장과 이유를 둔다.** 성생활, 임신 가능성, 음주·약물, 자살사고 등을 갑자기 묻지 않는다.
- **응급 증례는 속도가 다르다.** 긴 전체 병력보다 즉시 위험 확인과 병행 조치를 먼저 보여준다.
- **모든 문진은 요약과 확인으로 닫는다.** 단순히 마지막 질문에서 끝내지 않는다.
- **교육용 자료임을 명시하되, 면책 문구를 본문 앞에 길게 두지 않는다.** 짧은 문구를 페이지 하단에 둔다.

### 하지 않을 것

- 질환 개론, 병태생리, 역학 설명을 문진 앞에 길게 배치
- 모든 증례에 동일한 전신 문진을 기계적으로 삽입
- `Any chest pain, shortness of breath, nausea, vomiting, fever, chills...?`처럼 여러 질문을 한 문장에 몰아넣기
- 환자가 아직 말하지 않은 사실을 전제로 하는 유도 질문
- 의사가 정답 진단을 알고 심문하듯 체크리스트만 소진하는 대화
- 검사·약물·치료를 페이지의 주인공으로 만들기
- 실제 응급상황에서 문진을 계속해야 하는 것처럼 보이게 만들기
- 현재 Android case JSON을 검토 없이 그대로 공개하거나, 내부 정답·평가용 문구를 노출하기

## 4. 페이지에서 사용자가 보는 순서

### 권장 화면 구조

1. **제목**
   - 예: `Chest pain: a model history`
   - 그 아래 진료과 배지와 예상 소요 시간만 표시
2. **상황 카드**
   - 장소, 환자 나이대, 주호소를 최대 2~3줄로 제시
   - 진단명과 숨겨진 정답은 표시하지 않음
3. **Model interview**
   - 페이지의 핵심
   - Doctor / Patient 대화 18~28턴을 기본으로 함
   - 응급 증례는 10~18턴으로 더 짧게 구성
4. **Closing summary**
   - 의사가 환자에게 되돌려 말하는 3~5문장짜리 요약
   - 환자가 수정하거나 확인하는 한 턴 포함
5. **Flow at a glance**
   - 실제 대화가 지나온 순서를 5~8개 짧은 단계로 표시
6. **Do not miss**
   - 해당 증례에서 반드시 확인할 위험 신호 또는 분기점 3~5개
   - 해설 문단이 아니라 짧은 체크리스트로 표시
7. **Listen / Shadow**
   - 전체 듣기, 한 문장씩 재생, Doctor 역할만 따라 말하기
   - 오디오가 준비되지 않은 초기 버전에서는 생략 가능

`Flow at a glance`와 `Do not miss`는 대화 뒤에 둔다. 사용자가 먼저 완성된 문진을 보고, 필요할 때만 구조를 확인하게 하기 위함이다.

### 페이지에 노출하지 않는 제작용 정보

- 목표 진단
- 질문별 채점 기준
- 반드시 elicitation 해야 하는 사실 목록
- 위험 신호 누락 여부
- source case ID와 source hash
- 임상·언어 검토 상태

이 정보는 manifest 또는 HTML 주석 등 제작 파이프라인에만 보관한다.

## 5. 모든 모델 문진의 공통 뼈대

모든 페이지가 아래 순서를 한 글자도 바꾸지 않고 따를 필요는 없다. 다만 저자가 빠뜨린 부분을 확인하는 공통 기준으로 사용한다.

### A. 시작

- 자기소개와 역할
- 환자 확인
- 대화 동의 또는 편안한 진행 확인
- 개방형 첫 질문: `What brought you in today?`

### B. 환자의 첫 이야기

- 환자가 끊기지 않고 주호소와 맥락을 말할 짧은 공간
- 의사의 짧은 공감 또는 인정
- 환자가 여러 문제를 말하면 우선순위 합의

### C. 주호소 분석

- 시작 시점과 당시 상황
- 시간 경과와 변화
- 위치·성격·강도·빈도·지속시간 중 증상에 필요한 항목
- 악화·완화 요인
- 관련 증상
- 환자가 이미 시도한 대처와 효과

### D. 위험 신호와 중요한 감별 분기

- 해당 증례에 실제로 필요한 질문만 선택
- 위험 신호가 나오면 문진을 평소처럼 이어가지 않고 즉시 평가·도움 요청·안전 확보로 전환
- 음성 대본에서도 이 전환이 명확하게 들려야 함

### E. 배경 병력

- 관련 과거력과 수술력
- 현재 복용약, 일반의약품, 보충제, 최근 변경
- 약물 알레르기와 반응
- 관련 가족력
- 흡연, 음주, 약물, 직업·노출, 여행력 등 증례에 필요한 사회력

### F. 환자의 관점과 기능

- 증상이 수면, 일, 이동, 식사, 학업, 관계에 미친 영향
- 환자가 생각하는 원인
- 가장 걱정되는 점
- 오늘 진료에서 원하는 도움

### G. 마무리

- 의사의 요약
- 환자의 수정·추가 기회
- 다음 단계의 큰 방향을 쉬운 말로 설명
- 상황에 맞는 안전망 제공

## 6. 진료과별 시나리오 25개

아래의 `Android 기준 case`는 새 웹페이지의 출발점이다. 실제 공개 대본은 source case의 사실관계를 유지하되, 대화 목적에 맞게 별도로 집필하고 임상 검토한다.

### 6.1 내과계

#### 1) 소화기 / 복부 — 반복되는 복통과 묽은 변

- **공개 제목:** `Abdominal cramps and loose stools: a model history`
- **Android 기준 case:** `gi/gi_010.json`
- **교육 목표:** 만성 복부 증상을 시간축, 배변과의 관계, 식이·스트레스, 위험 신호로 정리하는 법
- **꼭 들어갈 것:** 통증 위치와 빈도, 배변 후 변화, 변 형태와 횟수, 야간 증상, 혈변, 체중 감소, 발열, 식이·카페인, 여행·항생제, 가족력, 업무 스트레스, 생활 영향
- **권장 흐름:** 개방형 질문 → 복통 분석 → 배변 양상 → 위험 신호 → 유발 요인 → 과거력·약 → 사회력·가족력 → 환자의 걱정 → 요약

#### 2) 심장혈관 — 2시간 전 시작된 흉통

- **공개 제목:** `Chest pain: a focused urgent history`
- **Android 기준 case:** `cardio/cardio_001.json`
- **교육 목표:** 잠재적 급성관상동맥증후군에서 짧고 우선순위가 분명한 문진
- **꼭 들어갈 것:** 정확한 발생 시각, 시작 당시 활동, 위치·성격·강도, 방사통, 지속 여부, 호흡곤란·발한·오심·실신, 운동과의 관계, 심혈관 과거력·위험인자, 코카인·각성제, 복용약과 알레르기
- **권장 흐름:** 즉시 상태 확인과 도움 요청 → 발생 시각 → 통증과 동반증상 → 핵심 위험인자 → 약·알레르기 → 짧은 요약 및 다음 단계
- **안전 메모:** 이 대본에서는 완전한 사회력이나 전신 문진보다 즉시 평가와 병행 조치를 먼저 모델링한다.

#### 3) 신경과 — 전조를 동반한 편측성 두통

- **공개 제목:** `A severe one-sided headache: a model history`
- **Android 기준 case:** `neuro/neuro_025.json`
- **교육 목표:** 두통의 양상과 이차성 두통 위험 신호를 구분해 묻는 법
- **꼭 들어갈 것:** 갑작스러운 최고 강도 여부, 이전 두통과의 비교, 위치·박동성·지속시간, 시각 전조, 오심·광과민·음과민, 발열·경부강직, 신경학적 증상, 임신 가능성, 외상, 진통제 사용, 유발 요인
- **권장 흐름:** 환자 서술 → onset/tempo → 두통 특징 → 전조·동반증상 → 위험 신호 → 과거 두통·약 → 기능 영향 → 요약

#### 4) 호흡기 — 운동할 때 생기는 쌕쌕거림과 숨참

- **공개 제목:** `Wheezing during exercise: a model respiratory history`
- **Android 기준 case:** `pulm/pulm_003.json`
- **교육 목표:** 천식 증상 빈도, 유발 요인, 조절 정도와 흡입기 사용을 자연스럽게 확인하는 법
- **꼭 들어갈 것:** 쌕쌕거림의 환자식 표현 확인, 기침·흉부 압박감, 운동·찬 공기·알레르겐, 주간 빈도, 야간 각성, 휴식 시 증상, 응급실·입원·삽관 과거, 흡입기 종류·사용 빈도·효과·기술, 흡연·전자담배
- **권장 흐름:** 증상 묘사 → 패턴과 유발 요인 → 조절 정도 → 중증도 과거력 → 약 사용 → 노출·흡연 → 목표 → 요약

#### 5) 내분비 — 심한 갈증, 잦은 소변, 체중 감소

- **공개 제목:** `Thirst, frequent urination, and weight loss: a model history`
- **Android 기준 case:** `endo/endo_021.json`
- **교육 목표:** 새로 발생한 고혈당 증상과 급성 악화 가능성을 체계적으로 확인하는 법
- **꼭 들어갈 것:** 증상 시작과 진행, 물 섭취량, 야간뇨, 식욕과 체중 변화, 피로·시야 흐림·감염, 오심·구토·복통·호흡 변화·의식 변화, 당뇨 가족력, 스테로이드·관련 약물, 생활 패턴
- **권장 흐름:** 세 증상의 시간축 → 정량화 → 급성 위험 신호 → 관련 증상 → 가족력·약 → 기능·걱정 → 요약 및 신속한 평가 설명

#### 6) 신장 — 거품뇨와 양측 발목 부종

- **공개 제목:** `Foamy urine and swollen ankles: a model renal history`
- **Android 기준 case:** `nephro/nephro_021.json`
- **교육 목표:** 소변 변화와 체액 저류를 함께 탐색하고 신장 위험요인을 확인하는 법
- **꼭 들어갈 것:** 거품뇨·혈뇨·소변량, 부종 시작과 진행, 아침 얼굴 부종, 체중 변화, 호흡곤란·기좌호흡, 당뇨·고혈압, 최근 감염, NSAID·보충제·한약, 신장질환 가족력
- **권장 흐름:** 소변 변화 → 부종과 체중 → 심폐·전신 증상 → 당뇨·고혈압 → 약·노출 → 가족력 → 일상 영향 → 요약

#### 7) 혈액종양 — 과다월경, 피로, 얼음이 당김

- **공개 제목:** `Fatigue and heavy periods: a model hematology history`
- **Android 기준 case:** `hemato/hemato_016.json`
- **교육 목표:** 빈혈 증상과 출혈 원인을 민감하고 구체적으로 확인하는 법

- **권장 흐름:** ABC와 현재 의식 확인 → 기전·시간 → 의식·기억 → 신경학적 위험 신호 → 항응고제·과거력 → 안전한 귀가 조건 → 요약과 안전망

#### 24) 재활의학과 — 허리에서 엉덩이와 허벅지로 뻗치는 통증

- **공개 제목:** `Low back pain spreading down the leg: a model rehabilitation history`
- **Android 기준 case:** `pmr/pmr_021.json`
- **교육 목표:** 통증 자체뿐 아니라 기능, 참여 제한, 회복 목표와 중대 위험 신호를 함께 묻는 법
- **꼭 들어갈 것:** 시작 동작, 통증 경로·성격, 저림·근력저하, 기침·자세와의 관계, 안장부위 감각, 배뇨·배변, 발열·체중 감소·암·외상·스테로이드, 걷기·수면·일·돌봄 영향, 두려움과 회피, 시도한 치료, 환자 목표
- **권장 흐름:** 통증 지도 → 신경 증상 → 중대 위험 신호 → 활동·참여 → 대처와 믿음 → 구체적 회복 목표 → 요약

#### 25) 가정의학과 — 5년 만의 예방 건강검진

- **공개 제목:** `A routine health check: a model family medicine history`
- **Android 기준 case:** `fm/fm_003.json`
- **교육 목표:** 증상이 없는 방문에서 의제 설정, 예방, 생활습관과 환자 우선순위를 함께 다루는 법
- **꼭 들어갈 것:** 환자가 가져온 의제, 기존 질환·수술·약·알레르기, 가족력, 혈압·당뇨·지질 위험, 흡연·음주·기타 물질, 식사·운동·수면·스트레스, 예방접종, 연령·위험 기반 선별검사 이력, 성건강·정신건강, 치과·시력, 변화 준비도
- **권장 흐름:** 의제 합의 → 전체 병력 업데이트 → 가족력 → 생활습관 → 정신·성건강 → 예방 이력 → 환자 우선순위와 변화 준비도 → 요약 및 공동 계획
- **범위 메모:** 선별검사 종류와 시기는 지역·연령·위험·최신 지침에 따라 달라지므로 대본에서 고정된 보편 규칙처럼 말하지 않는다.

## 7. 대본 집필 규격

### 길이

- 일반 외래: Doctor 12~18턴, Patient 12~18턴
- 응급·집중 문진: Doctor 7~12턴, Patient 7~12턴
- 영어 전체 분량: 약 450~750단어
- Closing summary: 60~110단어

길이보다 중요한 것은 한 질문에 한 목적만 두는 것이다. 환자 답변은 질문에 필요한 만큼만 자연스럽게 말하고, 평가용 case JSON의 모든 사실을 한 번에 쏟아내지 않는다.

### 문장 규칙

- 의사의 질문은 실제로 소리 내어 말할 수 있는 길이로 제한한다.
- 환자의 답은 불완전한 문장, 수정, 일상 표현을 적당히 포함하되 학습을 방해할 정도로 흐리지 않는다.
- `radiate`, `dyspnea`, `dysuria` 같은 용어보다 `spread`, `short of breath`, `burning when you pee` 같은 환자 친화적 표현을 우선한다.
- 질문을 묶어야 할 때도 한 번에 최대 두 개의 밀접한 항목만 묻는다.
- 의사는 환자 답을 짧게 반영한 뒤 다음 질문으로 넘어간다.
- 민감한 질문 앞에는 이유와 허락을 짧게 제시한다.
- 성별, 파트너, 임신 의도, 생활 방식은 추정하지 않는다.
- 통증 점수만 묻고 기능을 생략하지 않는다.
- 마지막에는 `Have I understood that correctly?`와 추가 발언 기회를 포함한다.

### 임상 규칙

- 공개 대본은 진단을 맞히는 모범답안이 아니라 **안전하고 구조적인 문진의 모범**이어야 한다.
- 정상·음성 소견도 의사가 실제로 물어 환자가 부인하는 대화로 확인한다.
- 위험 신호가 양성이면 그 뒤의 행동이 대본에 반영되어야 한다.
- 복용약은 처방약만이 아니라 일반의약품, 보충제, 최근 중단·변경까지 필요한 범위에서 확인한다.
- 알레르기는 이름뿐 아니라 어떤 반응이 있었는지 확인한다.
- 성건강 문진은 CDC의 5P 틀을 참고하되, 한 증례에 불필요한 항목까지 전부 캐묻지 않는다.
- 자살위험 문진은 완곡어법으로 피하지 않고 직접 질문하며, 양성 응답 뒤에는 추가 안전평가와 연결이 있어야 한다.

## 8. HTML 제작 시 권장 데이터 구조

한 페이지를 직접 손으로 복제하기보다 manifest와 template로 생성하는 편이 유지보수에 유리하다. 최소 필드는 다음과 같다.

```text
slug
specialty_key
specialty_label
source_case
source_sha256
public_title
setting
estimated_minutes
clinical_target_internal
doctor_patient_turns[]
closing_summary
flow_steps[]
do_not_miss[]
reviewed_on
clinical_reviewer
language_reviewer
language_standard
```

Android case가 바뀌면 `source_sha256` 불일치를 CI에서 잡도록 한다. 웹 문진 대본이 Android 앱의 환자 설정과 모순되는 것을 막되, 웹 대본 자체는 별도의 검토된 콘텐츠로 관리한다.

## 9. 제작·검토 순서

### 권장 1차 공개 6개

1. 심장혈관 — 흉통
2. 소화기 — 복통과 묽은 변
3. 정신건강의학과 — 우울감과 자살위험
4. 산부인과 — 생리통과 골반통
5. 소아청소년과 — 유아 변비
6. 응급의학과 — 경증 두부외상

이 여섯 개는 급성·만성, 신체·정신, 성인·소아, 일반·민감·응급 문진을 모두 시험할 수 있다. 먼저 이 구조로 템플릿의 밀도와 모바일 가독성을 검증한 뒤 나머지 19개를 같은 규격으로 확장한다.

### 페이지별 완료 조건

- source case의 핵심 사실과 모순 없음
- 증상 중심 제목이며 진단 정답을 미리 노출하지 않음
- 개방형 시작, 관련 위험 신호, 약·알레르기, 기능·환자 관점, 요약이 상황에 맞게 포함됨
- 긴 복합 질문과 유도 질문이 없음
- 응급 위험 신호가 양성이면 적절한 대화 전환이 있음
- 임상 검토와 `en-US` 언어 검토 완료
- 모바일에서 대화가 먼저 보이고 긴 설명이 앞을 막지 않음
- 키보드 탐색, 명도 대비, 화자 표기가 접근성 기준을 충족함
- source hash, sitemap, canonical URL, GA4 등 기존 정적 사이트의 검증 규칙과 통합됨
